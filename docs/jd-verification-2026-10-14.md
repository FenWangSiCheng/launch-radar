### 真实请求对照结果

在项目浏览器中打开购物车，通过开发者工具只检查加载请求。页面 HTML 正常返回 HTTP 200；`api.m.jd.com` 的 `pcCart_jc_getCurrentCart` 和 `pcCart_jc_cartSimple` 数据请求返回 HTTP 403。购物车请求预检返回 HTTP 200，实际 POST 返回 HTTP 403，响应体为空，响应头包含 `Server: jfe` 和 `X-Rp-Sdtoken` 字段；未保存字段值、凭据或请求参数。

本人扫码登录项目浏览器后，购物车仍显示「购物车跑丢了」；再次捕获 `pcCart_jc_getCurrentCart`，实际请求仍为 HTTP 403，预检为 HTTP 200。说明本次拒绝没有因重新登录解除。

对照日常 Chrome 的「用户2」资料：首次进入购物车能显示商品；打开开发者工具并刷新后，同一个购物车接口也返回 HTTP 403，正文变为「购物车跑丢了」。关闭开发者工具再次刷新仍未恢复，因此不能将拒绝单独归因于项目、自动化标记或开发者工具。检查完成后停止继续刷新。

已经确定当前加载失败的直接原因是京东接口网关拒绝购物车数据请求；没有证据表明链接路径错误或商品数据被项目删除。具体拒绝规则（访问频率、会话信誉、账号/IP、设备信息或其他规则）没有由空响应体公开，仍不能确定。两类浏览器均出现拒绝之后，不再做基于「只限制项目浏览器」假设的修改。未执行全选、结算、订单提交或付款。

### 缩短全选到结算的本地处理时间

Safari 原流程对每个候选结算元素分别读取嵌套关系、可见性和文字，且在准备结束后重复检查整页。现将候选筛选合并为页面内批量执行，将按钮文字与页面状态合并读取，并直接复用准备阶段返回的页面类型。已绑定全选时优先检查并点击该控件，省去整页寻找全选及再次定位的调用；只有未绑定全选时才使用原扫描路径。无付款状态文字时不再逐个扫描付款标题。

全选状态和按钮可用状态仍会检查；没有新增固定等待，商品金额仍不检查。通过涉及模块的语法检查、应用编译和签名检查。按此前要求未运行模拟下单，也未触发真实全选、结算或提交；未测量本次真实下单耗时，不能承诺具体提速幅度。
