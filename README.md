# Launch Radar

原生 macOS 多页面定时购买助手。人工登录、填写商品规格和地址、准备购买页面；工具按同一时间目标独立触发选定按钮。苹果官网任务可自动结账并选择支付宝。默认在下单前停止，开启自动立即下单后可由应用创建订单；支付宝付款由你完成。

## 启动

本机 Apple Silicon / macOS 14+ 可直接打开 `dist/Launch Radar.app`。包含 Node 和专用 Chromium，无需另外安装开发环境。应用是本地构建并签名，尚未办理 Developer ID 公证；不建议直接作为公开分发版本。

安装包：打开 `dist/Launch-Radar-macOS-arm64.dmg`，将 Launch Radar 拖到 Applications，再从「应用程序」启动。如果 macOS 阻止首次打开，尝试打开后到「系统设置 → 隐私与安全性」选择「仍要打开」。该安装包适用于 Apple 芯片 Mac、macOS 14 及以上。

重新生成安装包：`npm run package`，会重新构建应用、检查签名并生成及校验 DMG。

## 操作

安装包预置四个购买页面：Apple · Duo 星光白色 512GB、验证 · iPhone 18 Pro Max、天猫 · Apple 旗舰店购物车、京东 · 购物车。京东预置任务默认不参与运行、不自动提交订单。新电脑首次启动会保存这份默认列表，沿用打包时的参与任务、浏览器和自动结账/下单选项；需要重新登录、打开页面并绑定按钮。已有本地列表优先，删除全部页面后也不会重新添加默认页面。预置列表位于 `config/default-tasks.json`，不包含登录状态。

1. 添加页面名称及商品链接，选择浏览器并点击「打开」。苹果官网和京东默认 Safari，其他网站默认 Chrome；每个任务都能手动切换。Chrome 使用工具自带的专用 Chromium，不接管日常 Chrome。切换浏览器后需要重新打开并绑定按钮。
2. 人工登录并准备型号、地址和支付方式。能提前进入结算页的，停在结算页；不能提前结算的，停在购买页。
3. 点击「选按钮」，在浏览器中点击目标按钮。**这次点击只绑定目标，不会购买**。Esc 退出选择。
4. 回到应用，勾选需要参与的任务，点击「设置时间」，选择日期、时分和秒，然后「保存时间」。检查通过后自动开始等待，到点各页面独立运行，无需再启动倒计时。默认使用本机系统时区。
5. 想手动触发时，点击「立即运行」；定时等待期间也可提前运行，只执行这一轮，不会到原定时间再次运行。「取消定时」可取消尚未触发的任务。
6. 检查浏览器内实际订单、规格和价格，选择要付款的订单。多平台可能同时生成多个订单。

## Safari

- 新建苹果官网和京东任务默认 Safari；其他任务及演练默认 Chrome。已有任务保留手动选择。任务行和添加页面都有浏览器选项，选择会保存在本机。
- Safari 为每个任务打开一个独立的普通窗口，使用 Safari 自己的登录状态，可手动登录和准备商品。请保持该窗口只有一个标签页；添加标签页会停止自动操作，避免控制错误的页面。不要把任务页面移到其他窗口。
- 首次使用需在系统授权提示中允许 Launch Radar 控制 Safari。若拒绝，可到系统设置 → 隐私与安全性 → 自动化中调整。
- 选择按钮前，需要在 Safari 设置 → 高级开启网页开发者功能，再在开发者设置中开启「允许来自 Apple 事件的 JavaScript」。应用不会自行修改这项权限；未开启时会提示。此设置允许获准控制 Safari 的应用执行网页脚本，使用后可自行关闭。参考 [Apple 的开发者设置说明](https://developer.apple.com/documentation/safari-developer-tools/developer-settings)。
- Safari 当前仅支持主页面中的按钮，不支持内嵌框架里的按钮。Safari 使用网页脚本触发点击，网站可能拒绝这种点击；Apple 事件也会增加本机延迟，不能保证毫秒级触发或真实抢购成功率。
- Safari 演练在本机临时服务中运行，不访问苹果服务器。退出应用后保留 Safari 任务窗口以便核查进度，但演练服务会停止；任务重新启动时仍需重新打开和绑定。

## 苹果官网后续步骤

- 新添加的苹果官网任务默认勾选「自动继续苹果结账（选择支付宝）」；旧任务需手动勾选。关闭后恢复单次点击模式。
- 提前人工登录、选好型号、颜色、容量和购买选项，准备账户中的地址和付款信息；绑定当前的「继续」或其他中间按钮。工具不会替你选择型号、配送门店或编造个人信息。
- 到点点击后，识别明确的中间按钮，完成加入购物袋、查看购物袋、结账、配送地址、付款方式和订单核对。只识别已列入规则的按钮文字或苹果页面标记，不会在未知页面猜测普通「继续」。
- 缺少必填信息、需要登录/验证码、出现页面提示或多个候选按钮时暂停。手动处理后，在应用点击「继续结账」，立即继续剩余步骤。已执行但结果不明的步骤不会自动重复点击；需要人工核查并推进。已知中间步骤明确失败时可有限重试，详见下方异常恢复说明。
- 每步等待页面变化最多 45 秒，一次最多 12 个中间步骤（最终提交的重试另计：苹果 10 次，京东和天猫 50 次）；可以随时点击「停止」。已发出的点击无法撤回。
- 自动立即下单默认关闭。开启后可以点击订单提交按钮，但不点击立即支付或 Apple Pay；支付宝付款仍由你完成。
- 支持范围为 HTTPS 的 `apple.com`、`apple.com.cn` 及其子域。真实官网的语言、地区和页面结构可能变化；目前通过的是模拟结账验证，尚未验证真实首发购买成功率。

## 天猫 Apple 旗舰店

1. 点击「天猫苹果旗舰店」，粘贴具体商品链接或天猫/淘宝的完整分享文字，填写型号、颜色和容量等便于区分的任务名称。支持 HTTPS 的天猫/淘宝链接及 `tb.cn`、`taobao.cn` 分享短链接；纯淘口令需要先在手机打开商品并复制链接。链接域名检查不代表已验证店铺身份。
2. 默认使用专用 Chrome。点击「打开」，人工核对旗舰店身份、登录账号、选好规格和地址。分享短链接若不能在电脑打开，请替换为商品详情页链接。
3. 添加窗口可点击「使用淘宝购物车」直接填入 `https://cart.taobao.com/cart.htm`。登录后把购物车整理为本次要购买的商品（运行会自动全选），核对型号、颜色、容量和合计金额，再点击「选按钮」绑定「全选」。绑定过程不会购买。
4. 使用 Chrome，开启「自动继续天猫结账」，设置运行时间。绑定与倒计时准备时不改变勾选状态；到点全选购物车，确认选中且结算可用后点击结算，等待确认订单页。结算出现错误弹框时关闭并立即重试，最多额外 50 次。默认停在订单核对；开启「自动创建订单（点击立即支付，付款由本人完成）」后，点击确认页「立即支付」创建订单，出现弹框时关闭并最多额外重试 50 次，在付款页响铃提醒。付款需要你本人操作。如果提前能进入确认订单页，也可直接绑定「提交订单」或该订单确认页带金额的「立即支付」，需开启自动提交选项。

自动流程只识别淘宝购物车，以及 `buy.taobao.com` / `buy.tmall.com` 的已知确认订单路径中明确的「提交订单」，以及同时显示「确认收货地址」「确认订单信息」「付款详情」时带金额的「立即支付」。后者在该确认页用于创建订单；保留页面默认地址、支付方式和其他选项，点击后等待付款页，下单出现弹框时关闭并最多额外重试 50 次。支付宝及收银台中的付款按钮仍由本人点击。到点触发时自动全选购物车，结算前检查可读取的大于 0 的合计金额；缺货且未能勾选商品、金额为 0、缺少必填信息、登录、验证码或多个提交按钮时停下。等待后续页面最多 45 秒；点击结果不明确时不会重复提交。支持结算在原标签页跳转或打开一个新订单标签页。

商品详情页若需要绑定「立即购买」，请关闭自动继续结账，使用通用单次点击模式。天猫禁用按钮到点最多等 1.5 秒，预先绑定后手动刷新、跳转或按钮替换需重新绑定。新建天猫任务默认开启自动继续结账，自动提交订单默认关闭；已有任务需手动开启。已通过模拟结算、单次提交、新窗口及付款保护验证，尚未在真实淘宝账户中验证，不能保证真实抢购成功率。

## 京东购物车

1. 点击「京东购物车」，默认填入 `https://cart.jd.com/cart_index`。也可粘贴京东商品链接或完整分享文字（支持 HTTPS 的 `jd.com` 与 `3.cn` 分享链接）。默认使用 Safari，沿用 Safari 的登录状态；也可手动选择专用 Chrome。
2. 把购物车整理为本次要购买的商品（运行会自动全选），核对型号、规格、地址和合计金额，再点击「选按钮」绑定「全选」。可选取「全选」文字或复选框；原来绑定「去结算」的方式仍可使用。绑定不会勾选商品或结算。
3. 默认开启「自动继续京东结账」，绑定与倒计时准备时不改变勾选状态；到点全选购物车，确认选中且结算可用后自动点击去结算，等待订单确认。结算出现错误弹框时关闭并立即重试，最多额外 50 次。自动提交订单默认关闭；未勾选时停下并响铃提醒。
4. 传统确认页若有明确的「提交订单」，开启自动提交后可以创建订单，并在收银台停止；提交出现弹框时关闭并最多额外重试 50 次。提交结果不明时停止，同一轮「继续结账」保留提交记录与重试次数。
5. **新版「商品结算」页面的「立即支付」用于创建订单，再进入等待用户付款。** 勾选「自动创建订单（点击立即支付，付款由本人完成）」后，程序保留已选地址和付款方式并点击该按钮；未勾选时停在结算页。出现弹框时关闭并最多额外重试 50 次，与天猫一致；进入收银台或等待付款页面后停止，付款由本人完成。超时或结果不明时暂停，不重复创建订单；同一轮继续保留提交记录与重试次数。也可直接绑定该结算页的「立即支付」，需要勾选该选项。

京东自动流程只操作 `cart.jd.com/cart_index`（兼容 `cart.action`、`cart.html`）与 `trade.jd.com/shopping/order/getOrderInfo.action` 中明确的结算/提交按钮及新版 `.payment-action-submit` 中的「立即支付」，不检查商品金额。登录、验证码、必填信息不全、多个提交按钮或未知页面时暂停。Chrome 支持结算跳转到原标签页或新订单标签页；Safari 当前支持原标签页跳转，新开标签页时暂停并提示核查。普通等待为 45 秒；购物车结算错误弹框最多额外重试 50 次，排队最多等待 180 秒；停止会中断等待。商品详情页使用通用单次点击时需关闭自动继续京东结账。

2026-10-14 已读取本机 Chrome 的真实京东购物车及新版商品结算页，核对自定义「去结算」按钮、金额和整合支付结构，随后恢复购物车；未点击真实提交或支付。定时触发、传统提交、新窗口、弹框恢复与付款保护均通过模拟页面验证，不代表真实抢购成功率。传统「去结算 → 提交订单 → 收银台」流程亦见 [京东帮助中心](https://help.jd.com/user/issue/223-3958.html)。

## 速度与边界

- 浏览器提前启动、按钮提前绑定，执行服务使用单调时钟调度。界面刷新不参与提交调度。
- 不默认刷新页面。苹果商品开售时支持绑定按钮被替换；其他页面更换按钮或跳转后需重新绑定。苹果、天猫和京东自动流程在首次触发后识别各自的已知后续步骤；其他平台的多步结算需人工处理。
- 已启用按钮会提前进行不提交的点击检查。禁用按钮可绑定；苹果商品任务到点最多等 120 秒启用，其他任务等 1.5 秒启用或解除遮挡，超时后交给人工处理。
- 单次模式只点击一次；苹果后续流程默认每步点击一次，明确失败的已知中间步骤可有限重试，最终提交弹框可额外重试 10 次，不自动支付。点击返回成功只表示操作完成，不证明订单生成，也不证明锁定库存。
- 保存运行时间或立即运行后阻止空闲休眠。仍需保持 Mac 开机、联网，不合盖。系统调度延迟超过 500ms 会取消本轮，避免在睡眠恢复后突然提交。
- 停止能取消尚未发出的操作，无法撤回已经发出的点击。修改页面或重新运行前先核查订单。
- 时间指标是**本机发出点击调用**的延迟；Playwright 操作检查、浏览器输入、网络和平台队列还会增加时间。模拟测试不代表真实首发成功率。
- Apple、天猫和京东是使用场景；当前采用用户绑定按钮的通用方式，尚未认证各平台真实首发页面兼容性。

## 本地数据

任务名称和链接保存到本机应用偏好设置。Chrome 登录状态保存于 `~/Library/Application Support/LaunchRadar/Browser`，目录仅当前用户可访问。Safari 登录状态由 Safari 自己保存。应用不收集密码，不上传配置或日志；网页请求仍由浏览器发往对应平台。浏览器配置文件包含登录凭据，应按浏览器用户数据保护，不要分享。

退出后不会恢复倒计时或自动提交。重新启动需要再次打开页面、绑定按钮。

## 开发与验证

```sh
npm ci
npm run browser:install
npm test
npm run test:browser
npm run test:safari
npm run test:model
npm run build
npm run test:bridge
```

开发运行：`swift run`。需要本机 Swift/Xcode、Node；构建脚本会把当前架构 Node 与 Chromium 放入应用。Intel Mac 应在 Intel 环境安装依赖与浏览器后构建。

- `engine/scheduler.mjs`：统一时间、并行调度、取消、延迟保护。
- `engine/worker.mjs`：浏览器、人工按钮绑定、检查、单次点击。
- `engine/safari.mjs`：普通 Safari 窗口、Apple 事件、按钮选择和 DOM 检查。
- `engine/apple-flow.mjs`：苹果中间结账步骤识别、必填检查、暂停与继续。
- `engine/tmall-flow.mjs`：淘宝购物车检查、确认订单页单次提交及付款提醒。
- `engine/jd-flow.mjs`：京东购物车检查、传统订单提交和新版整合支付保护。
- `Sources/LaunchRadar`：原生窗口、任务管理、进度、执行记录。
- `docs/browser-test-results.json`：本次模拟浏览器验证结果。

实现参考 Taobao-Auto-Orders 的人工准备与定时提交思路，未复制其 GPL 源码。

Safari 适配器的自动测试使用 Chromium 作为 DOM 传输，覆盖绑定不提交、遮挡和禁用检查、失效按钮、取消选择、苹果多步结账及最终提交保护，以及京东嵌套按钮绑定、全选、原标签页跳转、整合支付创建订单、弹框重试和继续运行不重复提交；不等同于实际 Safari/Apple 事件验证。首次在本机 Safari 使用前，建议手动完成一轮 Safari 演练。


### 苹果完整流程

在 Safari 中提前选好规格、折抵换购和 AppleCare，登录并准备默认地址。选择「选按钮」后点击开售前禁用的「继续」，该操作仅绑定按钮。开启「自动继续苹果结账（选择支付宝）」并设置开售时间。应用到点等待按钮启用，支持按钮文字改变及按钮元素被替换，然后继续添加到购物袋 → 查看购物袋 → 结账 → 配送方式 → 默认地址 → 支付宝 → 检查订单。

需要自动创建订单时，在该任务上开启「自动点击立即下单（会创建真实订单）」。默认关闭，旧任务也不会自动开启。最终提交出现弹框时，不判断提示内容，关闭后立即重新提交，最多额外重试 10 次（首次加重试共最多 11 次）；该提示不代表服务器已经成功创建订单，必须在官网核查结果。支付宝付款、登录、验证码及缺少的地址信息由你处理。

自动化不会刷新整个商品页以探测开售；等待的是当前页面的按钮状态。如果官网必须手动刷新才能更新开售状态，应先刷新并重新绑定。自动流程不承诺开售库存、服务器排队及订单成功。

2026-10-13 新增回归覆盖：禁用「继续」元素被开售按钮替换、按钮的内部 value 与可见文字不同、配件页排除额外加购、支付宝选择、自动立即下单及默认不下单。完整订单提交仅在模拟页面验证，真实官网不创建测试订单。

## 拥挤与异常恢复（2026-10-13）

- 苹果和天猫识别可见网页提示、弹框与排队状态。明确的“系统繁忙/拥挤/网络异常/服务繁忙 + 操作/结算/请求失败 + 重试”提示，且只有一个明确关闭按钮时，可关闭提示并恢复中间步骤。普通“繁忙，请稍后再试”不足以证明失败，交给人工核查。
- 苹果已知结账中间步骤最多额外重试 3 次，依次等待 1、2、4 秒；京东、天猫购物车结算错误弹框关闭后立即重试，最多额外 50 次；重新检查当前页面、按钮与表单后再操作。加入购物袋不自动重试。最终创建订单出现弹框时采用下述平台重试额度。点击超时与未知结果不作为重试依据。
- 排队最多等待 180 秒，不刷新、不重复点击；排队结束后继续识别。普通页面变化等待为 45 秒，排队上限独立计算。停止会中断重试等待。
- 苹果点击最终提交后继续等待官网的订单成功文字或付款页；45 秒内未确认则显示结果不明。苹果最终下单、京东和天猫确认页创建订单后出现网页弹框，关闭后立即重新提交：苹果最多额外重试 10 次，京东和天猫最多额外重试 50 次；到订单成功或付款页立即停止。Chrome 原生弹框在最终提交后自动取消并触发同一重试规则；Safari 原生系统弹框仍需人工处理，网页内弹框支持自动关闭。关闭按钮不明确时暂停。没有自动查询订单历史的可靠接口，结果不明时由本人查看“我的订单”，程序不会根据超时再次下单。
- 苹果、京东和天猫暂停或结果不明时都可点击“继续结账”。同一轮继续会保留重试次数与已提交标记，保留最终提交弹框重试额度：苹果 10 次，京东和天猫 50 次；没有弹框时仅观察结果或继续未执行步骤。重新打开、重新绑定视为新一轮，请先核查订单。
